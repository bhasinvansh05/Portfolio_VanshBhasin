# Cloudflare configuration for vanshbhasin.dev

`vanshbhasin.dev` is a static site on GitHub Pages, proxied through Cloudflare.
GitHub Pages serves files and nothing else: it cannot set response headers and
cannot vary a response on a request header. Two agent-readiness problems
therefore cannot be fixed in this repository, and both need access to the
Cloudflare dashboard for the zone.

Nothing in `npm run build` depends on anything in this directory.

## 1. AI crawlers are blocked with HTTP 403 (highest impact)

Requests from AI crawler user agents never reach GitHub Pages. Cloudflare
answers them itself:

```console
$ curl -s -o /dev/null -w '%{http_code}\n' -A 'ClaudeBot/1.0' https://vanshbhasin.dev/
403
$ curl -s -o /dev/null -w '%{http_code}\n' -A 'Googlebot/2.1' https://vanshbhasin.dev/
200
```

The 403 is a 25-byte `text/plain` body from Cloudflare with a `cf-ray` header
and no `x-github-request-id`, which confirms the block happens at the edge
rather than at the origin. Affected agents observed: `GPTBot`, `ChatGPT-User`,
`ClaudeBot`, `PerplexityBot`.

This is Cloudflare's **Block AI Scrapers and Crawlers** setting (or an
equivalent WAF/bot rule). `robots.txt` cannot undo it — a crawler that gets a
403 never reads `robots.txt`. To fix it:

1. Cloudflare dashboard → the `vanshbhasin.dev` zone.
2. **Security → Bots**, and turn off *Block AI Scrapers and Crawlers*. On the
   free plan this is a single toggle. Check *Bot Fight Mode* in the same place;
   it also challenges non-browser clients.
3. **Security → WAF → Custom rules**, and remove or narrow any rule matching
   `cf.verified_bot_category` or AI user agents. If the security posture has to
   stay deny-by-default, add a *Skip* rule ahead of it instead:

   ```
   (http.user_agent contains "GPTBot")
   or (http.user_agent contains "ChatGPT-User")
   or (http.user_agent contains "OAI-SearchBot")
   or (http.user_agent contains "ClaudeBot")
   or (http.user_agent contains "Claude-User")
   or (http.user_agent contains "PerplexityBot")
   or (http.user_agent contains "Google-Extended")
   or (http.user_agent contains "DeepSeekBot")
   or (http.user_agent contains "Applebot-Extended")
   ```

   Action: *Skip* → all remaining custom rules, plus *Super Bot Fight Mode*.
4. Re-verify with the `curl` commands above. Every agent should return `200`.

The site's own `robots.txt` (generated by `scripts/prerender.mjs`) already
grants each of these agents an explicit `Allow: /`, so once the edge stops
blocking them there is nothing else to change.

## 2. Markdown content negotiation

`markdown-negotiation.js` is a Cloudflare Worker that implements the
[acceptmarkdown.com](https://acceptmarkdown.com) convention:

- `Accept: text/markdown` returns the page's Markdown mirror as
  `text/markdown; charset=utf-8`.
- Every negotiated response sends `Vary: Accept, Accept-Encoding`, so a cache
  cannot serve the HTML variant to a client that asked for Markdown.
- Both variants advertise the other through a `Link: <...>; rel="alternate"`
  header.
- A wildcard-only `Accept` (`*/*`) keeps getting HTML, so browsers, `curl` and
  ordinary crawlers are unaffected.

The Markdown mirrors it serves are produced by the build, so `/about/` always
has a matching `/about.md`. Those mirrors are already live and directly
fetchable without the Worker; the Worker only adds header-based negotiation.

### Deploying

With [Wrangler](https://developers.cloudflare.com/workers/wrangler/):

```bash
npx wrangler deploy infra/cloudflare/markdown-negotiation.js \
  --name vanshbhasin-markdown-negotiation \
  --compatibility-date 2025-01-01 \
  --route 'vanshbhasin.dev/*'
```

Or paste the file into **Workers & Pages → Create Worker** in the dashboard and
add a route of `vanshbhasin.dev/*`.

Deploy the Worker only after step 1 is done. While the edge still returns 403
for AI user agents, negotiation makes no difference to the agents it is for.

### Verifying

```bash
# Markdown variant
curl -sI -H 'Accept: text/markdown' https://vanshbhasin.dev/ | grep -iE 'content-type|vary'
# expect: content-type: text/markdown; charset=utf-8
#         vary: Accept, Accept-Encoding

# HTML variant is unchanged
curl -sI -H 'Accept: text/html' https://vanshbhasin.dev/ | grep -iE 'content-type|vary'
# expect: content-type: text/html; charset=utf-8
#         vary: Accept, Accept-Encoding
```

The Accept-parsing and path-mapping logic is pure and covered by
`npm test` (see `scripts/verify-agent-readiness.mjs`), so a change to the
negotiation rules fails the test suite rather than silently shipping.
